# AI 기반 한국어 대화 감정 흐름 분석 시스템

2026-2학기 산학캡스톤디자인 · 팀 안성맞춤 (신제민 · 김예준 · 박기태)

상담 축어록을 올리면 **발화 순서에 따른 감정 변화를 그래프로** 보여주고,
**감정이 크게 바뀐 지점(전환점)** 을 찾아 표시합니다.

A4 15장짜리 상담 기록을 처음부터 읽지 않고도 감정의 흐름을 파악하는 것이 목표입니다.

---

## 폴더 구성

| 폴더 | 내용 | 상태 |
|---|---|---|
| `frontend/` | React 화면 (로그인, 화면 1~5) | 구현 완료 |
| `backend/` | FastAPI 서버 — 로그인, 파싱, 마스킹, 분석, 저장 | 동작 (KcELECTRA 모델 연결) |
| `model/` | 감정 분류 모델 설정 · 토크나이저 · 성능 요약 (가중치는 별도 다운로드) | 학습 완료 · 대분류 Macro F1 0.765 |
| `samples/` | 시연·평가용 가상 축어록 10편과 정답 파일(`answers.json`) | 튜닝용 6편, 평가용 4편 |
| `scripts/` | 개발용 보조 스크립트 (서버에는 올리지 않음) | `make_dummy.py`, `evaluate.py` (샘플 정답 비교·튜닝) |

각 폴더의 실행 방법과 세부 구조는 해당 폴더의 README를 참고하세요.

## 실행하기

### 처음 받았을 때 (또는 모델이 연결된 버전을 처음 받았을 때)

모델 가중치는 용량 때문에 저장소에 없습니다. 서버를 켜기 전에 아래를 먼저 해 주세요.

1. `model/README_emotion_model.md`의 구글 드라이브 링크에서 `final_kcelectra_multitask.pt`를 받아 **`model/` 폴더**에 넣습니다.
   `git status`에 이 파일이 보이지 않아야 정상입니다 (`.gitignore`의 `*.pt`).
2. `backend` 폴더에서 패키지를 설치합니다. torch가 포함되어 있어 몇 분 걸립니다.
   ```bash
   pip install -r requirements.txt
   ```
3. 서버를 **처음 켤 때** Hugging Face에서 KcELECTRA 원본 모델(약 1GB)을 내려받습니다.
   `C:\Users\<사용자>\.cache\huggingface`에 저장되므로 두 번째부터는 받지 않습니다.
   `symlinks`, `UNEXPECTED` 경고는 무시해도 됩니다.

모델만 따로 확인하려면 `backend` 폴더에서 `python -m app.services.emotion_model`을 실행합니다.

### 평소 실행

**백엔드와 프론트엔드를 둘 다 켜야** 화면이 동작합니다.
프론트가 서버에서 분석 결과를 받아오기 때문입니다.

```bash
# 터미널 1 — 백엔드 (MySQL 필요, 자세한 준비는 backend/README.md)
cd backend
.venv\Scripts\activate
uvicorn app.main:app --reload

# 터미널 2 — 프론트엔드
cd frontend
npm install
npm run dev
```

http://localhost:5173 에 들어가면 로그인 화면이 먼저 나옵니다.
회원가입하거나, `backend/seed.py`로 만든 시연 계정 `demo`로 로그인한 뒤 축어록 txt를 올리면 결과 화면이 나옵니다.

서버는 켜질 때 감정 모델을 한 번 불러오므로 전보다 몇 초 더 걸립니다.
`--reload`로 켜 둔 상태에서는 코드를 저장할 때마다 모델을 다시 불러옵니다.

## 처리 흐름

```
파일 업로드 → 파싱 → 마스킹 → 분석용 텍스트 정리 → 감정 분석 → 후처리 → DB 저장 → 화면
                                                      ↑              ↑
                                              KcELECTRA 모델     대표 감정 · 전환점 · 요약
```

- **감정 분석** (`backend/app/services/analyzer.py`): 내담자 발화마다 감정 6종의 확률(합이 1)을 냅니다.
  모델을 불러오는 코드는 팀원이 작성한 `emotion_model.py`이고, `analyze()`는 그 결과에서 6개 점수만 꺼냅니다.
- **전환점** (`backend/app/services/postprocess.py`): 앞뒤 발화 몇 개의 평균 감정 분포가 가장 크게 달라지는
  지점(봉우리)을 찾습니다. 샘플 정답으로 튜닝해 `window=3`, `threshold=0.5`로 정했습니다.

## 데이터

학습 데이터는 **AI Hub「감성 대화 말뭉치」** 를 사용합니다.

- 대분류 6종: 불안 · 분노 · 상처 · 슬픔 · 당황 · 기쁨
- 각 대분류마다 소분류 10종 (총 60종)
- 학습용 51,630건 / 검증용 6,641건

**데이터 파일은 저장소에 포함하지 않습니다.** 재배포가 제한되고 용량도 커서,
각자 [AI Hub](https://aihub.or.kr)에서 신청 후 내려받아 주세요.

모델 성능 평가 결과는 `model/result/`에 **요약만** 올립니다. 문장별 예측 파일(`*predictions*.csv`)에는
검증 데이터 원문이 들어 있어 `.gitignore`로 막아 두었습니다.

| | 정확도 | Macro F1 |
|---|---|---|
| 대분류 6종 | 77.1% | 0.765 |
| 소분류 58종 | 51.6% | 0.505 |

감정별 성적과 혼동 행렬은 `model/result/multitask_validation_summary.json`에 있습니다.
상처↔슬픔, 당황↔불안이 서로 가장 많이 헷갈립니다 (9~11%).

`samples/`의 축어록 10편은 시연·평가용으로 직접 작성한 **가상 축어록**이며 AI Hub 문장이 아닙니다.

`frontend/src/data/dummy.json`은 예외로 포함되어 있습니다.
문장은 위 말뭉치에서 추출한 실제 문장이고, 감정 점수는 개발용으로 생성한 값입니다.
백엔드의 `seed.py`가 이 파일을 DB에 넣어, 시연 계정 `demo` 소유의 데모 세션(`demo-001`)을 만듭니다.

## 팀 규칙

- **같이 고쳐야 하는 파일 쌍**이 있습니다. 한쪽만 고치면 화면과 분석이 어긋납니다.
  - `frontend/src/types.ts` ↔ `backend/app/schemas.py` — 데이터 모양
  - `frontend/src/constants/nonverbal.ts` ↔ `backend/app/services/text_rules.py` — 비언어 판별 규칙
  - `frontend/src/pages/LoginPage.tsx`의 `validate()` ↔ `backend/app/schemas.py`의 `SignupRequest` — 가입 규칙
- 비밀번호·API 키는 `.env`에만 두고, 저장소에는 `.env.example`로 키 이름만 공유합니다.
- **올리지 않는 파일**: 모델 가중치(`*.pt` 등), AI Hub 데이터와 원문이 든 파일. 모두 `.gitignore`로 막혀 있습니다.
- 다른 사람이 올린 커밋을 받을 때는 `git status`가 깨끗한지 먼저 확인한 뒤 `git pull` 합니다.
- 업로드된 원본 파일은 서버에 저장하지 않으며, 이름·연락처는 자동으로 마스킹합니다.
- 커밋 메시지는 무엇을 했는지 한 줄로 적습니다. (예: `카카오톡 파서 초안 작성`)

## 남은 일 체크리스트

### 모델 · 분석

- [x] **평가 스크립트** (`scripts/evaluate.py`): 샘플 10편을 실제 모델로 분석해 `samples/answers.json`과 비교.
      결과는 화면에만 출력 (`python scripts/evaluate.py --window 3 --threshold 0.5`)
      — 발화별 정답률 엄격 87.6% · 완화 93.3% (225개)
- [x] **전환점 튜닝**: `window=3`, `threshold=0.5`. 튜닝용 6편 F1 0.863, **평가용 4편 F1 1.000**
      (같은 개수를 무작위로 찍으면 0.328). 후보끼리 차이가 전환점 1개 수준이라,
      모델 오분류를 섞었을 때 덜 무너지는 값을 고름. 샘플이 실제 축어록보다 감정이 또렷해 점수가 높게 나온 것임
- [x] **확신 낮음 기준**: `LOW_CONFIDENCE = 0.7` (백엔드 `postprocess.py`, 프론트 `constants/emotions.ts` 두 곳).
      1등 점수 0.7 미만은 정답률 약 53%, 이상은 96%
- [x] **복합 감정 표시**: 0.7 미만 발화의 91%는 점수가 두 감정으로 나뉜 경우라 "확신 낮음"보다 "복합"이 정확함.
      흐리게 하지 않고 1·2등을 함께 표시, 요약 카드도 "복합 발화"로

      `emotion_model.py`에서 원본 가중치를 받지 않도록 바꿀지 팀원과 협의
- [ ] `.env`: `COOKIE_SECURE=true`, 배포용 DB 접속 정보, `DEMO_PASSWORD`
- [ ] `main.py`의 CORS 허용 주소를 배포 주소로

- [ ] 업로드 크기 검사를 파일을 다 읽기 전에 하도록
- [ ] 로그인 시도 횟수 제한
- [ ] 아주 긴 한 줄(예: 5천 자 이상) 거부 — 특정 정규식이 긴 줄에서 매우 느려짐
