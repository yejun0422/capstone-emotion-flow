# AI 기반 한국어 대화 감정 흐름 분석 시스템

2026-2학기 산학캡스톤디자인 · 팀 안성맞춤 (신제민 · 김예준 · 박기태)

상담 축어록을 올리면 **발화 순서에 따른 감정 변화를 곡선으로** 보여주고,
**감정이 크게 바뀐 지점(전환점)** 을 찾아 표시합니다.

A4 15장짜리 상담 기록을 처음부터 읽지 않고도 감정의 흐름을 파악하는 것이 목표입니다.

---

## 폴더 구성

| 폴더 | 내용 | 상태 |
|---|---|---|
| `frontend/` | React 화면 (화면 1~5) | 화면 1~4 구현 완료 |
| `backend/` | FastAPI 서버 — 파싱, 마스킹, 분석, 저장 | 업로드~결과 조회 동작 (임시 분석기) |
| `model/` | 감정 분류 모델 학습 · 평가 | 학습 진행 예정 |
| `scripts/` | 더미 데이터 생성 등 보조 스크립트 | `make_dummy.py` |

각 폴더의 실행 방법과 세부 구조는 해당 폴더의 README를 참고하세요.

---

## 실행하기

지금은 **백엔드와 프론트엔드를 둘 다 켜야** 화면이 동작합니다.
프론트가 서버에서 분석 결과를 받아오기 때문입니다.

```bash
# 터미널 1 — 백엔드 (MySQL 필요, 자세한 준비는 backend/README.md)
cd backend
.venv\Scripts\activate
uvicorn app.main:app --reload

# 터미널 2 — 프론트엔드
cd frontend
npm install
npm run dev
```

http://localhost:5173 에서 축어록 txt를 올리면 결과 화면이 나옵니다.

## 처리 흐름

```
파일 업로드 → 파싱 → 마스킹 → 분석용 텍스트 정리 → 감정 분석 → 후처리 → DB 저장 → 화면
                                                      ↑
                                            현재는 임시 분석기(랜덤 점수)
```

감정 분석 부분만 아직 가짜입니다. 모델이 완성되면 `backend/app/services/analyzer.py`의
함수 내부만 교체하면 전체가 실제 분석으로 바뀝니다.

## 화면 구성

| 번호 | 화면 | 상태 |
|---|---|---|
| 1 | 홈 · 업로드 | ✅ |
| 2 | 분석 진행 (진행률 표시) | ✅ |
| 3 | **결과 대시보드** — 요약 지표 · 감정 색 띠 · 감정 곡선 · 전사본 | ✅ |
| 4 | 발화 상세 패널 | ✅ |
| 5 | 세션 목록 | 예정 |

화면 3이 핵심입니다. 곡선·색 띠·전사본이 선택된 발화 번호 하나를 공유해서,
어느 쪽을 클릭해도 나머지가 함께 반응합니다.

## 데이터

학습 데이터는 **AI Hub「감성 대화 말뭉치」** 를 사용합니다.

- 대분류 6종: 불안 · 분노 · 상처 · 슬픔 · 당황 · 기쁨
- 각 대분류마다 소분류 10종 (총 60종)
- 학습용 51,630건 / 검증용 6,641건

**데이터 파일은 저장소에 포함하지 않습니다.** 재배포가 제한되고 용량도 커서,
각자 [AI Hub](https://aihub.or.kr)에서 신청 후 내려받아 주세요.

`frontend/src/data/dummy.json`은 예외로 포함되어 있습니다.
문장은 위 말뭉치에서 추출한 실제 문장이고, 감정 점수는 개발용으로 생성한 값입니다.
백엔드의 `seed.py`가 이 파일을 DB에 넣어 데모 세션(`demo-001`)을 만듭니다.

## 설계 결정 기록

논의를 거쳐 정한 사항입니다. 바꾸려면 팀 논의 후 이 표도 함께 고쳐 주세요.

| 주제 | 결정 | 이유 |
|---|---|---|
| 학습 데이터 | AI Hub 감성대화 말뭉치 (KOTE 대신) | 대화 단위 구성이고 대분류 6종이 이미 제공되어 프로젝트 목적과 맞음 |
| 감정 체계 | 대분류 6종 우선, 소분류는 상세 정보로만 | 시각화 가독성, 소분류 성능 미달 시에도 시스템 유지 |
| 입력 형식 | 축어록 txt 중심, CSV 지원, 카톡은 현 수준 유지 | 프로젝트 목적은 상담 기록 분석. 카톡은 테스트용으로 남겨두되 추가 처리는 하지 않음 |
| 회기 단위 | 한 파일 = 한 회기 | 회기 분리는 사용자가 판단할 문제로 봄 |
| 비언어 정보 | 괄호류는 종류 구분 없이 모두 분석에서 제외, 화면에는 회색으로 표시 | 기관마다 축어록 양식이 달라 괄호 종류로 의미를 구분할 수 없음. 목적은 텍스트 감정 분석이지 상담 통계가 아님 |
| 원문 저장 | 원문 하나만 저장, 분석용 텍스트는 저장하지 않고 규칙으로 재생성 | 두 벌을 저장하면 어긋날 위험. 원본 파일을 저장하지 않으므로 재분석 시 원문이 필요 |
| 말줄임표 | 분석에 포함. 특수문자(`․` `…`)만 일반 마침표로 통일 | 축어록은 편집하지 않는 것이 원칙이고, 모델도 말줄임표를 처리할 수 있음 |
| 마스킹 표기 | `〈이름〉` `〈전화번호〉` 처럼 홑화살괄호 사용 | `[ ]`나 `( )`를 쓰면 비언어 정보로 오인됨 |
| 발화 번호 | 원본 번호 대신 1부터 다시 매김 | 한 파일 한 회기 전제에서 원본 번호를 보존할 필요가 적음 |

## 팀 규칙

- **같이 고쳐야 하는 파일 쌍**이 있습니다. 한쪽만 고치면 화면과 분석이 어긋납니다.
  - `frontend/src/types.ts` ↔ `backend/app/schemas.py` — 데이터 모양
  - `frontend/src/constants/nonverbal.ts` ↔ `backend/app/services/text_rules.py` — 비언어 판별 규칙
- 비밀번호·API 키는 `.env`에만 두고, 저장소에는 `.env.example`로 키 이름만 공유합니다.
- 업로드된 원본 파일은 서버에 저장하지 않으며, 이름·연락처는 자동으로 마스킹합니다.
- 커밋 메시지는 무엇을 했는지 한 줄로 적습니다. (예: `카카오톡 파서 초안 작성`)
